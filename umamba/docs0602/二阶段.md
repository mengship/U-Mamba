# 第一章二阶段实施方案

## 一、阶段二的定位

如果把第一章拆成两个推进阶段，那么当前我们已经基本完成了阶段一：

- `gated reconstruction`
- `minimal cross-view interaction`
- 模块级前向测试通过
- 远程 GPU 下真实 `SS2D` 路径跑通

阶段一解决的是：

`RTHD 模块本身够不够强`

而阶段二要解决的问题不再是“模块里再加什么小功能”，而是：

`这个增强版 RTHD 应该如何在整网中部署，才能更像一个完整的方法，而不是局部替换块`

所以阶段二的关键词是：

- `网络级部署`
- `编解码器差异化配置`
- `结构恢复导向解码器`


## 二、阶段二的核心目标

阶段二的目标不是继续堆参数，而是把第一章从：

`增强版 TriView/RTHD 模块`

推进为：

`具备可控部署策略的多轴空间建模网络`

具体来说，阶段二最值得做的三件事是：

1. `partial decoder RTHD`
2. `encoder / decoder 分离配置`
3. `stage-wise deployment`

这三件事的优先级建议为：

`1 -> 2 -> 3`


## 三、阶段二改动包 D：Partial Decoder RTHD

### 3.1 核心动机

当前 [`UNetResDecoder_RTHD`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:453) 的策略是：

- 只要 `use_rthd_decoder=True`
- 就让所有 decoder stage 都使用 `RTHDBlock`

这个做法有两个问题：

1. 解码器被“完全对称化”了，但对称不一定最优
2. 第一章仍然容易被理解成“把 encoder 的思想机械复制到 decoder”

因此，阶段二最值得先做的，是让解码器支持：

- `不用 RTHD`
- `只在前几个 stage 用 RTHD`
- `所有 stage 都用 RTHD`

### 3.2 建议新增参数

在 `UMambaEnc_RTHD` 及其构建入口中新增：

```python
use_rthd_decoder: bool = True
rthd_stages_decoder: List[int] = None
decoder_rthd_mode: str = "full"   # "none", "partial", "full"
```

参数含义：

- `use_rthd_decoder`
  是否启用 RTHD 解码器

- `rthd_stages_decoder`
  指定 decoder 哪些 stage 使用 `RTHDBlock`

- `decoder_rthd_mode`
  便于 trainer 直接读懂当前实验配置

### 3.3 需要修改的类

- [`UNetResDecoder_RTHD`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:453)
- [`UMambaEnc_RTHD`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:612)
- [`get_umamba_enc_rthd_3d_from_plans()`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:693)

### 3.4 具体实现建议

#### 当前解码器结构

现在每个 decoder stage 固定是：

```python
BasicResBlock(...)
RTHDBlock(...)
optional BasicBlockD(...)
```

#### 建议改成条件式结构

对于每个 decoder stage，增加判断：

```python
use_rthd_this_stage = decoder_stage_idx in self.rthd_stages_decoder
```

如果启用：

```python
stage_blocks = [
    BasicResBlock(...),
    RTHDBlock(...),
    ...
]
```

如果不启用：

```python
stage_blocks = [
    BasicResBlock(...),
    BasicBlockD(...),
    ...
]
```

### 3.5 推荐的最小版本

第一版不要一下子加很多模式，建议只支持：

- `decoder_rthd_mode="none"`
- `decoder_rthd_mode="partial"`
- `decoder_rthd_mode="full"`

并约定：

- `none`
  使用原始 `UNetResDecoder`

- `partial`
  使用 `UNetResDecoder_RTHD`，但只在 `rthd_stages_decoder` 中插入 `RTHDBlock`

- `full`
  当前完全对称版本

### 3.6 这一改动的论文意义

这一步会让第一章从：

`编码区里的多轴空间建模`

变成：

`编码提取 + 解码恢复联合设计`

也就是说，第一章不再只是“encoder 结构创新”，而是开始讨论：

- tri-view 适合在哪些恢复阶段继续使用
- 解码器是否需要和编码器同构
- 多轴空间建模在特征恢复阶段的价值


## 四、阶段二改动包 E：Encoder / Decoder 分离配置

### 4.1 核心动机

当前 [`get_umamba_enc_rthd_3d_from_plans()`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:693) 里使用的是统一的：

```python
rthd_config
```

这意味着：

- 编码器和解码器共享同一套 tri-view 参数
- `view_mode/share_weights/scan_mode/use_local_window`
- 以及阶段一新增的增强参数

这在阶段一是可接受的，但到了阶段二就不够细了。

因为：

- 编码器更偏全局语义抽取
- 解码器更偏结构恢复和边界细化

它们不一定应该共享完全相同的 RTHD 配置。

### 4.2 建议新增参数

在构建入口中新增：

```python
rthd_config_encoder: dict = None
rthd_config_decoder: dict = None
```

并保留兼容：

```python
rthd_config: dict = None
```

推荐逻辑：

- 如果只传 `rthd_config`
  encoder/decoder 共同使用

- 如果传 `rthd_config_encoder` / `rthd_config_decoder`
  则各自独立生效

### 4.3 需要修改的位置

- `UMambaEnc_RTHD.__init__`
- `ResidualMambaEncoder_RTHD`
- `UNetResDecoder_RTHD`
- `get_umamba_enc_rthd_3d_from_plans`

### 4.4 推荐先分开的参数

阶段二第一版不需要所有参数都分开，建议只让下面这些先支持独立控制：

- `reconstruction_mode`
- `cross_view_interaction`
- `use_local_window`
- `window_size`

一个合理假设是：

- 编码器：
  更重视多轴扫描和跨视图交互

- 解码器：
  更重视结构恢复，未必需要同样强的交互

### 4.5 推荐的第一版实验组合

- `E1`
  encoder: enhanced RTHD  
  decoder: baseline RTHD

- `E2`
  encoder: enhanced RTHD  
  decoder: lightweight RTHD

- `E3`
  encoder: enhanced RTHD  
  decoder: enhanced RTHD

这一步的意义在于：

- 让阶段一的增强不再只是“统一复制”
- 而是开始形成“编解码器职责差异化”的设计逻辑


## 五、阶段二改动包 F：Stage-wise Deployment

### 5.1 核心动机

当前网络级策略主要只有：

- `rthd_stages`
- `use_rthd_decoder`

但这还不够表达“不同分辨率层对 tri-view 建模需求不同”。

阶段二更好的做法是：

让不同 stage 使用不同的 RTHD 强度。

### 5.2 建议新增参数

```python
rthd_stages_encoder: List[int] = None
rthd_stages_decoder: List[int] = None
stage_window_sizes_encoder: List[int] = None
stage_window_sizes_decoder: List[int] = None
```

### 5.3 最值得先做的部分

我不建议阶段二一开始就把 `stage_window_sizes` 全部做完，因为会拉高实现复杂度。  
更实际的顺序是：

#### 第一步
先做：

- `rthd_stages_encoder`
- `rthd_stages_decoder`

#### 第二步
如果前一步结果好，再做：

- `stage_window_sizes_encoder`
- `stage_window_sizes_decoder`

### 5.4 论文表达上的价值

这个方向的好处是：

- 第一章不仅有“模块创新”
- 还有“部署策略创新”

也就是说，第一章不只是提出：

`一个新的 tri-view 模块`

而是提出：

`一种多轴空间建模在不同网络层级中的部署原则`


## 六、阶段二最推荐的实施顺序

如果从实现成本、论文收益、与现有代码兼容性综合考虑，建议按下面顺序推进。

### 阶段 2.1：Partial Decoder RTHD

先让解码器支持：

- none
- partial
- full

这是阶段二最重要的一步。

### 阶段 2.2：Encoder / Decoder 分离配置

在前一步基础上，把：

- `rthd_config_encoder`
- `rthd_config_decoder`

分开。

### 阶段 2.3：Stage-wise Deployment

最后再加：

- `rthd_stages_encoder`
- `rthd_stages_decoder`

如果还有精力，再做：

- `stage_window_sizes_*`


## 七、建议的最小可行参数设计

为了避免阶段二一上来就把配置系统搞得很复杂，建议采用“最小新增”策略。

### 7.1 网络构造参数

```python
use_rthd_decoder: bool = True
decoder_rthd_mode: str = "full"  # "none", "partial", "full"
rthd_stages_encoder: List[int] = None
rthd_stages_decoder: List[int] = None
rthd_config_encoder: dict = None
rthd_config_decoder: dict = None
```

### 7.2 推荐默认行为

- 不传新参数时：
  保持当前行为不变

- `decoder_rthd_mode="full"`：
  保持当前完全对称版本

- `decoder_rthd_mode="partial"`：
  默认只在 decoder 前两个 stage 使用 RTHD

- `decoder_rthd_mode="none"`：
  回退到原始卷积解码器


## 八、阶段二的最小实验设计

### 8.1 解码器部署实验

- `D1`: encoder only
- `D2`: encoder + partial decoder
- `D3`: encoder + full decoder

研究问题：

- tri-view 建模在恢复阶段是否同样有益
- 完全对称是否真的优于部分部署

### 8.2 编解码器差异化配置实验

- `E1`: encoder enhanced / decoder basic
- `E2`: encoder enhanced / decoder lightweight
- `E3`: encoder enhanced / decoder enhanced

研究问题：

- 编码器和解码器是否应共享同一套多轴建模策略

### 8.3 网络级部署实验

- `F1`: shallow-heavy
- `F2`: deep-heavy
- `F3`: full-stage

研究问题：

- tri-view 结构更适合浅层还是深层


## 九、阶段二与第一章写作的关系

阶段一完成后，第一章已经可以说：

- 提出了一种增强版 RTHD 模块

但阶段二完成后，第一章就可以升级为：

- 提出了一种具有可控部署策略的多轴空间建模网络

也就是说，第一章的叙事将从：

`模块创新`

扩展成：

`模块创新 + 网络级部署原则`

这会明显增强论文厚度。


## 十、最终建议

阶段二不需要一开始追求特别复杂，最值得先做的是：

1. `partial decoder RTHD`
2. `encoder / decoder 分离配置`

只要这两步做出来，第一章就已经从“增强版 tri-view 模块”变成“具备网络级部署策略的完整方法”了。

所以，阶段二最简洁的行动指南可以概括为：

`先让解码器支持部分部署，再让编解码器配置分离。`

这两步做完后，如果实验结果有提升，再继续扩展 `stage-wise window` 和更细的层级部署策略。
