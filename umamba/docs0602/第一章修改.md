# 第一章修改分析

## 一、当前第一章的现状判断

当前第一章的主体创新，主要集中在 [`rthd_modules.py`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/rthd_modules.py:1) 中的 `TriViewProjection`、`TriViewVMambaBlock` 和 `RTHDBlock`，并通过 [`UMambaEnc_RTHD.py`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:1) 挂载到编码器和解码器。

这套设计已经形成了一个清晰的主线：

- 3D 特征先做三视图分解
- 每个 2D 视图用 `SS2D` 做轻量扫描
- 再通过广播重建回 3D
- 外围再叠加 DS-Conv 和残差

这条线本身是成立的，但目前仍然偏“模块内部改造”，因此容易显得第一章厚度不够。更具体地说，当前版本主要有以下特点：

- 创新基本集中在 `TriViewVMambaBlock`
- 三视图之间几乎没有显式交互，更多是“各自处理后再融合”
- 投影方式较简单，主要是 `mean/max/slice`
- 重建方式较简单，主要是 `broadcast + average` 或 `weighted`
- 网络级策略还不够丰富，主要是“在哪些 stage 使用 RTHD”
- 第一章目前更像“编码区结构优化”，而不是“完整的多轴空间建模体系”

所以，第一章后续修改的重点，不应该只是继续加几个消融开关，而应该把它从“一个模块”扩展成“一个围绕多轴空间建模与结构恢复的完整方案”。


## 二、第一章应该坚持的边界

虽然第一章需要增厚，但不建议把第二章、第三章的内容强行塞进来。为了让三章之间分工清楚，第一章最好仍然聚焦在以下主题：

- `多轴空间表达`
- `轻量化三视图序列建模`
- `降维后的结构保持与恢复`

不建议在第一章里过多展开：

- 缺失模态鲁棒性
- foundation model 适配
- 视觉语言提示
- 大量不确定性和可信分割内容

这些内容更适合第二章或第三章。


## 三、基于当前代码可继续增厚的几个方向

下面这些方向都可以继续围绕第一章展开，而且和现有代码衔接自然。

### 3.1 从“多轴分解”升级为“多轴交互”

当前的 `TriViewProjection -> _process_view -> TriViewReconstruction` 更像“三条分支并行处理”，但多轴信息之间并没有真正发生中间层交互。

这会导致一个问题：

- 三视图虽然被建立了，但更像三个彼此独立的 2D 编码器
- 最终融合主要发生在重建阶段
- 模型没有显式学习“某个视图如何帮助另一个视图”

如果要增强第一章厚度，最值得补的一条线就是：

`多轴协同建模`

可行改法：

- 在 `TriViewVMambaBlock` 中加入 `cross-view interaction`
- 在 axial、coronal、sagittal 分支之间增加轻量交互
- 交互可以放在扫描前、扫描后，或窗口级别

可以设计成以下几种形式：

- `pre-fusion`
  视图进入各自 `SS2D` 之前先做一次轻量信息交换

- `post-fusion`
  三个视图扫描后先做交互，再进入重建

- `window-level fusion`
  局部窗口内不只扫描单视图，还允许窗口级跨视图融合

这一方向的意义很大，因为它能把你的方法从“tri-view decomposition”提升为“multi-axis collaborative modeling”。


### 3.2 从“静态投影”升级为“自适应投影”

当前 [`TriViewProjection`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/rthd_modules.py:78) 里的投影方式比较基础：

- `mean`
- `max`
- `slice`

这三种方式容易理解，也适合做基础消融，但从论文章节厚度上看，显得比较“工程化”。

可以进一步改成：

- `adaptive projection`
  根据输入特征自适应决定每个视图如何压缩缺失维度

- `axis-attentive projection`
  在 D/H/W 三个方向上学习不同的投影权重，而不是简单平均

- `hybrid projection`
  同时结合 mean、max 和可学习加权，再由网络自动融合

对应落点：

- 修改 `TriViewProjection`
- 增加轻量投影权重生成器
- 为每个视图生成更有结构感知能力的 2D 表示

这一条的价值在于：

- 仍然完全属于第一章
- 不需要引入第二章的多模态内容
- 能直接增强“空间降维”这件事本身的合理性


### 3.3 从“重建广播”升级为“结构感知重建”

当前 [`TriViewReconstruction`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/rthd_modules.py:124) 的核心方式是：

- 各视图沿缺失维度广播
- 再做平均或加权融合

这一步是当前第一章最容易被质疑的地方之一，因为它本质上还是一个比较粗的恢复过程。

如果第一章要增厚，我认为这里是最值得做的第二个重点。

可行改法：

- `gated reconstruction`
  让三个视图在每个空间位置产生门控系数，而不是固定权重

- `residual reconstruction`
  将重建结果与原始 3D 特征做门控残差融合，而不是直接平均后输出

- `anisotropic reconstruction`
  不同维度方向使用不同的重建策略，以适应 MRI 的各向异性

- `structure-preserving reconstruction`
  在重建阶段显式利用局部 3D 卷积补偿广播带来的结构缺失

对应落点：

- 修改 `TriViewReconstruction`
- 在 `RTHDBlock` 中加入重建后的补偿卷积或门控融合

这一方向的价值在于：

- 直接回应“3D 降到 2D 会不会损伤结构信息”
- 非常贴合第一章标题里的“结构保持”
- 比继续调 `scan_mode` 更像真正的方法创新


### 3.4 从“共享扫描模块”升级为“视图角色分工”

当前你的消融实验已经验证了 `share_weights=True/False`，但这还是停留在“是否共享参数”。

更进一步的思路不是简单不共享，而是：

`三个视图承担不同角色`

可行改法：

- axial 更偏局部纹理
- coronal 更偏纵向结构
- sagittal 更偏横向结构

实现上可以不是完全独立参数，而是：

- 共享主干 + 轻量视图专属 adapter
- 共享 `SS2D` + 每个视图一个小型 gating head
- 共享扫描核 + 不同视图不同的投影/重建偏置

对应落点：

- 主要修改 `TriViewVMambaBlock`
- 比完全独立三个 `SS2D` 更轻
- 比完全共享更有表达能力

这一条很适合写成：

`视图差异化建模`

它仍然属于第一章，而且能在不明显增加参数的前提下提升论述深度。


### 3.5 从“模块级改造”升级为“网络级多轴部署策略”

当前 [`ResidualMambaEncoder_RTHD`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:138) 已经支持：

- `rthd_stages`
- 编码器中部分 stage 使用 RTHD
- 解码器选择是否使用 RTHD

但目前这些策略还没有被充分上升为第一章的一部分。

如果要增强第一章体系感，可以把“RTHD 如何在整网中部署”本身作为一个研究点。

可行改法：

- `encoder-only deployment`
  只在编码器使用 RTHD，强调全局语义提取

- `shallow-heavy deployment`
  浅层更多使用 RTHD，深层回归普通 Mamba 或卷积

- `deep-heavy deployment`
  只在中高层使用 RTHD，突出高语义层的多轴建模

- `asymmetric encoder-decoder deployment`
  编码器和解码器采用不同的 tri-view 强度

- `stage-wise adaptive deployment`
  不同 stage 使用不同窗口大小、不同视图策略

这一方向的意义在于：

- 第一章不再只是一个模块
- 而是“模块 + 网络级部署原则”
- 论文表达上会更成熟


### 3.6 从“对称解码器”升级为“结构恢复导向解码器”

当前 [`UNetResDecoder_RTHD`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:453) 采用的是比较直接的完全对称思路：

- 上采样
- 拼接 skip
- BasicResBlock
- RTHDBlock

这个设计能工作，但它更像是“把编码器思想复制到解码器”，而不是围绕恢复任务进行专门设计。

如果第一章要增厚，可以考虑让解码器承担明确的“结构恢复”角色。

可行改法：

- `skip-aware RTHD decoder`
  解码器中的 tri-view 处理不只看上采样特征，也显式建模 skip 的视图结构

- `gated skip fusion`
  在 skip 和 decoder feature 拼接前先做门控

- `decoder-side reconstruction refinement`
  解码器的 RTHD 不强调降维，而强调重建后细节恢复

- `partial decoder RTHD`
  只在前 1 到 2 个解码 stage 使用 RTHD，末端保留卷积细化

这一方向仍然属于第一章，因为它本质上还是在讨论：

- tri-view 特征如何被恢复成高质量 3D 分割表示


### 3.7 从“轻量化模块”升级为“可解释轻量化”

当前第一章里“轻量化”的论据主要来自复杂度和显存，但还可以进一步往论文表达上加强。

建议在第一章中增加两个分析维度：

- `视图贡献分析`
  axial/coronal/sagittal 分别对 WT/TC/ET 哪些区域贡献更大

- `空间位置贡献分析`
  tri-view 对边界、中心区、增强区域、小目标区域的提升是否一致

虽然这部分不一定要求立即改代码，但可以为第一章增加很强的解释性。


## 四、最值得优先推进的修改组合

如果从“工作量、创新性、与第一章契合度”综合考虑，我认为最推荐优先推进的不是很多条同时做，而是下面这三条组合。

### 方案 A：多轴交互 + 结构感知重建

这是我最推荐的组合。

优点：

- 直接增强第一章主线
- 不会跑偏到第二章
- 很容易形成新的方法命名

可以形成的故事线：

- 不是简单三视图分解
- 而是三视图协同建模
- 并且通过结构感知重建减少降维损伤

建议修改位置：

- `TriViewVMambaBlock`
- `TriViewReconstruction`
- `RTHDBlock`


### 方案 B：自适应投影 + 视图角色分工

这条更偏“多轴空间表达增强”。

优点：

- 理论上更贴合“多轴空间建模”
- 参数开销相对可控
- 可和现有 `share_weights` 消融形成自然对比

建议修改位置：

- `TriViewProjection`
- `TriViewVMambaBlock`


### 方案 C：网络级部署 + 解码恢复专门化

这条更偏“把模块提升为体系”。

优点：

- 能让第一章从单模块研究变成整网设计
- 更容易写出一节完整的“网络架构设计”
- 可以和现有 trainer / 配置系统自然衔接

建议修改位置：

- `UMambaEnc_RTHD.py`
- 编码器 `rthd_stages`
- 解码器 `UNetResDecoder_RTHD`

## 六、建议的第一章最终结构

如果按照当前代码基础继续推进，第一章可以整理为如下结构：

### 6.2 基础框架

### 6.4 改进二：结构感知重建

- 自适应重建

### 6.5 改进三：网络级轻量部署

- stage-wise RTHD

### 6.6 实验验证

- 精度
- 显存

- 结构恢复可视化


## 七、最终结论

当前第一章的问题，不是 `RTHD` 方向错了，而是它还停留在“一个很好的模块级想法”。

如果要把这一章真正做厚，最关键的不是继续增加类似 `view_mode/share_weights/scan_mode/use_local_window` 的开关，而是让它在以下三个层面同时成立：

- `模块层面`
  三视图扫描本身更强

- `交互层面`
  三个视图之间真正协同

- `恢复层面`
  降维后能更好保住 3D 结构信息

在此基础上，再补上：

- `网络级部署策略`
- `解码恢复专门化`
- `可解释轻量化分析`

这样第一章就会从“编码区优化”升级成“一个完整的多轴空间建模与结构恢复方法章节”。
