# 第一章可实施版本

## 一、目标

这份文档不是继续讨论“第一章还能往哪里扩”，而是把最值得推进的内容收束成可直接实施的版本。  
目标是从当前的 `RTHD` 出发，在不跳出第一章主题的前提下，把方法从“编码区中的三视图模块优化”推进成“多轴空间协同建模 + 结构感知恢复 + 网络级部署”的完整方案。

结合当前代码结构和实现成本，最推荐优先推进的不是很多条同时做，而是下面三个改动包：

1. `改动包 A：多轴交互`
2. `改动包 B：结构感知重建`
3. `改动包 C：网络级非对称部署`

这三个包之间是兼容的，建议推进顺序为：

`A -> B -> C`

也就是先增强 `rthd_modules.py` 内部表达能力，再把改进自然挂到编码器/解码器。


## 二、改动包 A：多轴交互

### 2.1 核心目标

解决当前 `TriViewVMambaBlock` 中“三视图彼此独立扫描、只在最后重建时融合”的问题。  
把当前方法从：

`tri-view decomposition`

提升为：

`multi-axis collaborative modeling`

### 2.2 需要修改的类

- [`TriViewVMambaBlock`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/rthd_modules.py:184)
- 可选：[`RTHDBlock`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/rthd_modules.py:546)

### 2.3 建议新增参数

在 `TriViewVMambaBlock.__init__` 中增加：

```python
cross_view_interaction: bool = False
interaction_mode: str = "post"   # "pre", "post"
interaction_type: str = "gate"   # "gate", "residual"
interaction_ratio: float = 0.25
```

参数含义：

- `cross_view_interaction`
  是否启用跨视图交互

- `interaction_mode`
  交互发生在扫描前还是扫描后

- `interaction_type`
  采用门控融合还是残差融合

- `interaction_ratio`
  交互分支的隐层压缩比例，控制额外参数量

### 2.4 建议新增子模块

在 `TriViewVMambaBlock` 中增加一个轻量交互模块，例如：

```python
self.view_interaction = nn.Sequential(
    nn.Conv2d(dim * 3, hidden_dim, kernel_size=1, bias=False),
    nn.GELU(),
    nn.Conv2d(hidden_dim, dim * 3, kernel_size=1, bias=False),
)
```

其中：

- `hidden_dim = max(dim // 4, 16)` 或按 `interaction_ratio` 计算

如果担心参数多，可以分三个 head：

- `axial_gate`
- `coronal_gate`
- `sagittal_gate`

### 2.5 前向流程建议

#### 方案 A1：扫描后交互，优先推荐

这是最稳妥的第一版。

当前流程：

1. projection
2. 分别 `_process_view`
3. reconstruction

改成：

1. projection
2. axial/coronal/sagittal 分别 `_process_view`
3. 将三个输出对齐到可拼接形式
4. 做 `post interaction`
5. 再 reconstruction

伪代码：

```python
axial_out = self._process_view(axial, 'axial')
coronal_out = self._process_view(coronal, 'coronal')
sagittal_out = self._process_view(sagittal, 'sagittal')

if self.cross_view_interaction:
    axial_out, coronal_out, sagittal_out = self._cross_view_interact(
        axial_out, coronal_out, sagittal_out
    )
```

### 2.6 实现细节难点

这里最大的技术点不是“怎么交互”，而是：

- axial 形状是 `(B, C, H, W)`
- coronal 是 `(B, C, D, W)`
- sagittal 是 `(B, C, D, H)`

它们的二维平面不一致，不能直接 `cat`。

因此第一版建议不要强行做原始平面上的直接拼接，而采用：

`先投回 3D，再在 3D 空间做交互，再重新分配回视图`

更具体地说：

1. 先把三个视图临时 broadcast 成 3D
2. 在 3D 上做轻量交互卷积或门控
3. 再从交互后的 3D 张量中回读 axial/coronal/sagittal 引导项

这样比硬对齐三种 2D 平面更稳。

### 2.7 更建议的最小可行版

为了降低实现复杂度，可以不直接改 `TriViewVMambaBlock` 的每个 2D 分支，而是：

- 扫描后先用当前 `TriViewReconstruction` 临时重建一个 `fused_3d`
- 对 `fused_3d` 用一个轻量 `Conv3d(1x1x1)` 生成三路 gate
- 再把 gate 分别投回 2D 视图，用于修正三个分支

这能实现“跨视图交互”，而且形状最容易处理。

### 2.8 建议实验

最小实验组：

- `Baseline`: 当前 `#6`
- `A1`: `cross_view_interaction=False`
- `A2`: `cross_view_interaction=True, interaction_mode='post', interaction_type='gate'`
- `A3`: `cross_view_interaction=True, interaction_mode='post', interaction_type='residual'`

观察指标：

- Dice
- HD95
- ET 小区域指标
- 参数量/FLOPs 增量

### 2.9 风险点

- 视图形状天然不对齐，直接 2D 交互容易写乱
- 额外交互过重会削弱“轻量化”的卖点
- 第一版不要追求太复杂，先做 `post interaction + gate`


## 三、改动包 B：结构感知重建

### 3.1 核心目标

解决当前 `TriViewReconstruction` 过于依赖：

- 广播
- 平均融合
- 全局静态权重

的问题。

这一步是第一章最值得增强的第二个核心点，因为它直接决定：

`从 2D tri-view 回到 3D 时，结构信息能不能被保住`

### 3.2 需要修改的类

- [`TriViewReconstruction`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/rthd_modules.py:124)
- [`RTHDBlock`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/rthd_modules.py:546)

### 3.3 建议新增参数

在 `TriViewVMambaBlock` 和 `RTHDBlock` 的构造参数中透传：

```python
reconstruction_mode: str = "broadcast"
reconstruction_refine: bool = False
reconstruction_gate: bool = False
reconstruction_residual: bool = True
```

可选模式建议扩展为：

- `broadcast`
  当前版本

- `weighted`
  当前已有全局 learnable weights

- `gated`
  新增，位置相关 gate

- `refined`
  新增，重建后加 3D 细化

### 3.4 建议的最小实现

#### 方案 B1：位置相关 gated reconstruction

在 `TriViewReconstruction` 里不再只用一个 `(3,)` 的全局权重，而是让模型对每个空间位置生成三路融合系数。

实现思路：

1. 先得到：
   - `axial_3d`
   - `coronal_3d`
   - `sagittal_3d`
2. 拼接成：
   - `(B, 3C, D, H, W)`
3. 用轻量 `1x1x1 Conv3d` 生成 `(B, 3, D, H, W)` 的 gate
4. softmax 后加权融合

伪代码：

```python
fusion_feat = torch.cat([axial_3d, coronal_3d, sagittal_3d], dim=1)
gate_logits = self.gate_conv(fusion_feat)   # (B, 3, D, H, W)
gate = torch.softmax(gate_logits, dim=1)

out = (
    axial_3d * gate[:, 0:1]
    + coronal_3d * gate[:, 1:2]
    + sagittal_3d * gate[:, 2:3]
)
```

这个版本最推荐，因为：

- 实现简单
- 完全贴合“结构感知重建”
- 很容易写实验故事

#### 方案 B2：重建后细化

在 `TriViewReconstruction` 输出 3D 张量后，增加一个很轻量的 refinement：

```python
self.refine = nn.Sequential(
    nn.Conv3d(dim, dim, kernel_size=3, padding=1, groups=dim, bias=False),
    nn.Conv3d(dim, dim, kernel_size=1, bias=False),
)
```

然后：

```python
out = out + self.refine(out)
```

这一版很适合和 `gated reconstruction` 配合。

### 3.5 建议修改点

当前 `TriViewReconstruction` 没有 `dim` 信息，所以如果要做卷积式 gated/refine，有两个办法：

#### 办法 1：重构 `TriViewReconstruction`

让它在 `__init__` 接受 `dim`：

```python
class TriViewReconstruction(nn.Module):
    def __init__(self, dim: int, mode: str = "broadcast", use_refine: bool = False):
```

这是最干净的做法。

#### 办法 2：在 `RTHDBlock` 外围做 refine

保持 `TriViewReconstruction` 只负责基础融合，然后在 `RTHDBlock` 中增加：

```python
self.reconstruction_refine = DepthwiseSeparableConv3d(...)
```

第一版我更建议 `办法 1`，结构更清晰。

### 3.6 建议实验

最小实验组：

- `B1`: `broadcast`
- `B2`: `weighted`
- `B3`: `gated`
- `B4`: `gated + refine`

重点观察：

- ET Dice
- ET HD95
- 边界可视化
- 是否出现结构模糊减少

### 3.7 风险点

- 如果 `gate_conv` 太重，会破坏轻量化叙事
- 如果先做 gate 再做外层残差，可能导致表达重复
- 第一版建议只用 `1x1x1 gate + optional ds refine`


## 四、改动包 C：网络级非对称部署

### 4.1 核心目标

让第一章从“模块设计”上升到“网络级设计原则”。  
当前虽然已经有：

- `rthd_stages`
- `use_rthd_decoder`

但还不够系统。

### 4.2 需要修改的类

- [`ResidualMambaEncoder_RTHD`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:138)
- [`UNetResDecoder_RTHD`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:453)
- [`UMambaEnc_RTHD`](/Users/flash/Documents/Data_Work/07_学习积累/果壳/projectcode/U-Mamba/umamba/nnunetv2/nets/UMambaEnc_RTHD.py:612)

### 4.3 建议新增参数

在网络级增加：

```python
rthd_stages_encoder: List[int] = None
rthd_stages_decoder: List[int] = None
decoder_rthd_mode: str = "none"   # "none", "partial", "full"
stage_window_sizes: List[int] = None
```

含义：

- `rthd_stages_encoder`
  编码器哪些 stage 用 RTHD

- `rthd_stages_decoder`
  解码器哪些 stage 用 RTHD

- `decoder_rthd_mode`
  解码器使用策略

- `stage_window_sizes`
  每个 stage 的窗口大小不同，而不是统一 `8`

### 4.4 解码器建议改法

当前 `UNetResDecoder_RTHD` 默认所有 stage 都用 `RTHDBlock`。  
第一版建议不要继续维持“完全对称必须最好”的假设，而是支持：

- `none`
  解码器不用 RTHD

- `partial`
  只在前 1 到 2 个 stage 用 RTHD

- `full`
  所有解码 stage 用 RTHD

具体实现：

在 `UNetResDecoder_RTHD.__init__` 中，按 `decoder stage index` 判断是否插入 `RTHDBlock`。

伪代码：

```python
use_rthd_this_stage = decoder_stage_idx in self.rthd_stages_decoder

if use_rthd_this_stage:
    stage_blocks = [BasicResBlock(...), RTHDBlock(...)]
else:
    stage_blocks = [BasicResBlock(...), BasicBlockD(...)]
```

### 4.5 stage-wise window 策略

当前 `window_size` 是全局统一的。  
更适合第一章的增强方式是：

- 浅层窗口小
- 深层窗口大

示例：

```python
stage_window_sizes = [4, 4, 8, 8, 0]
```

其中：

- `0` 可以代表该 stage 走 global flatten 或不走 tri-view

这能形成更完整的“复杂度分配策略”。

### 4.6 建议实验

最小实验组：

- `C1`: encoder only
- `C2`: encoder + partial decoder
- `C3`: encoder + full decoder
- `C4`: encoder only + stage-wise windows

重点看：

- Dice / HD95
- 显存
- 吞吐量
- 哪种部署最划算

### 4.7 风险点

- 如果同时改模块内部和网络级部署，实验量会变大
- partial decoder 的实现需要仔细和 `n_conv_per_stage_decoder` 对齐
- 第一阶段先把接口加好，不要一次把所有组合都跑满

## 八、最终建议

如果只选一句话作为下一步实施原则，那就是：

`先把 tri-view 做成交互式和结构感知的，再把它变成网络级可控部署`

对应到实际开发上，就是：

1. 先做 `cross_view_interaction`
2. 再做 `gated reconstruction`
3. 最后做 `partial decoder + stage-wise deployment`

这样推进，第一章会很自然地从：

`一个编码区中的 Recursive Tri-view Hierarchical Decomposition 模块`

升级成：

`一个具备多轴协同建模、结构保持恢复和网络级部署策略的完整脑肿瘤分割方法`
