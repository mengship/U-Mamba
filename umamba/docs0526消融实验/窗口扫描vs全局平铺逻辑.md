# 固定窗口 vs 全局平铺：实现逻辑详解

## 🎯 你的问题

> "窗口扫描与全局平铺版是什么逻辑，串行还是并行后合并的逻辑？"

**答案**：两种模式是**互斥的**，不是并行关系。根据 `use_local_window` 参数选择其中一种。

---

## 📊 两种模式对比

### 模式 1: 全局平铺（Global Flatten）

**配置**: `use_local_window=False`

**逻辑**: **直接处理整个特征图**

```python
# 伪代码
输入: (B, C, H, W) = (2, 64, 32, 32)
  ↓
直接送入 VMamba
  ↓
输出: (B, C, H, W) = (2, 64, 32, 32)
```

**特点**：
- ✅ 简单直接
- ✅ 全局感受野
- ❌ 序列长度长（H×W = 1024）
- ❌ 计算复杂度高

### 模式 2: 固定窗口（Fixed Window）

**配置**: `use_local_window=True`

**逻辑**: **分窗 → 并行处理 → 合并**

```python
# 伪代码
输入: (B, C, H, W) = (2, 64, 32, 32)
  ↓
Step 1: 窗口分割
  ↓
(B*num_windows, C, window_size, window_size) = (32, 64, 8, 8)
  ↓
Step 2: 并行处理所有窗口（一次前向传播）
  ↓
(B*num_windows, C, window_size, window_size) = (32, 64, 8, 8)
  ↓
Step 3: 窗口合并
  ↓
输出: (B, C, H, W) = (2, 64, 32, 32)
```

**特点**：
- ✅ 序列长度短（window_size² = 64）
- ✅ 局部建模能力强
- ✅ 计算效率高
- ❌ 需要分窗和合并操作

---

## 🔍 详细实现逻辑

### 全局平铺模式（代码第 434-451 行）

```python
if not self.use_local_window:
```

**处理流程**：

```
输入: (B, C, 32, 32)
  ↓
VMamba 扫描整个 32×32 平面
序列长度 = 32 × 32 = 1024
  ↓
输出: (B, C, 32, 32)
```

**计算特点**：
- 一次前向传播
- 处理 1024 长度的序列
- 全局感受野

### 固定窗口模式（代码第 454-478 行）

```python
else:  # use_local_window=True
    # Step 1: 窗口分割
    windows, (H_pad, W_pad) = window_partition(view, self.window_size)
    # windows: (B * num_windows, C, window_size, window_size)
    
    # Step 2: 对每个窗口进行VMamba扫描
    windows_out = self.vmamba_2d(windows)
    
    # Step 3: 窗口合并
    out = window_reverse(windows_out, self.window_size, H_pad, W_pad, H, W)
```

**处理流程**：

```
输入: (B, C, 32, 32) = (2, 64, 32, 32)
  ↓
Step 1: 窗口分割 (window_size=8)
  ↓
(B*nH*nW, C, 8, 8) = (2*4*4, 64, 8, 8) = (32, 64, 8, 8)
  ↓
Step 2: VMamba 并行处理 32 个窗口
每个窗口序列长度 = 8 × 8 = 64
  ↓
(32, 64, 8, 8)
  ↓
Step 3: 窗口合并
  ↓
输出: (B, C, 32, 32) = (2, 64, 32, 32)
```

**计算特点**：
- 一次前向传播处理所有窗口（**并行**）
- 每个窗口处理 64 长度的序列
- 局部感受野

## 💡 关键问题：并行还是串行？

### 答案：**并行处理**

```python
# Step 2: 对每个窗口进行VMamba扫描
windows_out = self.vmamba_2d(windows)
# windows: (B * num_windows, C, window_size, window_size)
```

**关键理解**：
- 所有窗口被**堆叠在 batch 维度**上
- `(B * num_windows, C, 8, 8)` = `(32, 64, 8, 8)`
- VMamba 一次前向传播处理所有 32 个窗口
- **这是并行的**，不是串行的！

### 为什么是并行？

```python
# 窗口分割后
windows.shape = (32, 64, 8, 8)
# 32 = 2 (batch) × 16 (num_windows)

# VMamba 看到的是 32 个独立的样本
# 它不知道这些样本来自同一个特征图的不同窗口
# 所以会并行处理所有 32 个样本

# 这就像处理 batch_size=32 的数据一样
```

## 📊 计算复杂度对比

### 假设特征图尺寸：32×32，window_size=8

| 模式 | 序列长度 | 窗口数量 | 总计算量 | 并行度 |
|-----|---------|---------|---------|--------|
| **全局平铺** | 1024 | 1 | O(1024 × C) | 低 |
| **固定窗口** | 64 | 16 | O(16 × 64 × C) | **高** |

**注意**：
- 总计算量相同：`1024 × C = 16 × 64 × C`
- 但固定窗口的**并行度更高**
- 每个窗口的序列更短，计算更高效

## 🔬 实际性能对比

### 全局平铺

**优势**：
- ✅ 全局感受野
- ✅ 可以捕获长距离依赖

**劣势**：
- ❌ 序列长度长（1024）
- ❌ Mamba 的计算复杂度与序列长度线性相关
- ❌ 显存占用大

### 固定窗口

**优势**：
- ✅ 序列长度短（64）
- ✅ 计算效率高
- ✅ 显存占用小
- ✅ 局部建模能力强

**劣势**：
- ❌ 局部感受野（但通过三视图融合可以弥补）
- ❌ 需要额外的分窗和合并操作

## 📈 实际例子

### Stage 0: 特征图 128×128

#### 全局平铺
```
序列长度 = 128 × 128 = 16,384
一次处理 16,384 长度的序列
```

#### 固定窗口（window_size=8）
```
窗口数量 = (128/8) × (128/8) = 16 × 16 = 256
每个窗口序列长度 = 8 × 8 = 64
并行处理 256 个不重叠窗口，每个窗口 64 长度
```

**对比**：
- 全局：处理 1 个 16,384 长度的序列
- 固定窗口：并行处理 256 个 64 长度的序列
- **固定窗口更高效！**

## ✅ 总结

### 回答你的问题

| 问题 | 答案 |
|-----|------|
| 串行还是并行？ | **并行** |
| 如何并行？ | 所有窗口堆叠在 batch 维度，一次前向传播 |
| 是否合并？ | 是，通过 `window_reverse` 合并 |
| 哪个更快？ | **固定窗口**（序列更短） |

### 核心逻辑

```
全局平铺: 直接处理 → 输出
固定窗口: 分窗 → 并行处理 → 合并 → 输出
```

### 关键代码

```python
# 固定窗口的并行处理（不重叠）
windows = (B * num_windows, C, window_size, window_size)
windows_out = self.vmamba_2d(windows)  # 一次处理所有窗口（并行）
```
