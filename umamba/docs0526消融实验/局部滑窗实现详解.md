# 局部滑窗机制实现详解

## 📖 背景

局部滑窗（Local Window）机制借鉴了 **Swin Transformer** 和 **LoMamba** 的思想，将大的特征图分割为多个不重叠的小窗口，在每个窗口内独立进行 Mamba 扫描，从而：

1. **减少序列长度**：从 O(H×W) 降至 O(window_size²)
2. **降低计算复杂度**：Mamba 的复杂度与序列长度线性相关
3. **增强局部建模能力**：每个窗口专注于局部特征

---

## 🔧 核心实现

### 1. `window_partition` - 窗口分割

```python
def window_partition(x: torch.Tensor, window_size: int) -> Tuple[torch.Tensor, Tuple[int, int]]:
    """
    将2D特征图分割为不重叠的局部窗口
    
    输入: (B, C, H, W)
    输出: (B * num_windows, C, window_size, window_size)
    """
    B, C, H, W = x.shape
    
    # Step 1: 计算padding，确保H和W能被window_size整除
    pad_h = (window_size - H % window_size) % window_size
    pad_w = (window_size - W % window_size) % window_size
    
    if pad_h > 0 or pad_w > 0:
        x = F.pad(x, (0, pad_w, 0, pad_h))  # padding到右边和下边
    
    H_pad, W_pad = H + pad_h, W + pad_w
    
    # Step 2: 计算窗口数量
    nH = H_pad // window_size  # 垂直方向窗口数
    nW = W_pad // window_size  # 水平方向窗口数
    
    # Step 3: 重塑张量，分割为窗口
    # (B, C, H_pad, W_pad) -> (B, C, nH, window_size, nW, window_size)
    windows = x.view(B, C, nH, window_size, nW, window_size)
    
    # Step 4: 调整维度顺序，将窗口维度移到batch维度
    # (B, C, nH, window_size, nW, window_size) -> (B, nH, nW, C, window_size, window_size)
    windows = windows.permute(0, 2, 4, 1, 3, 5).contiguous()
    
    # Step 5: 合并batch和窗口维度
    # (B, nH, nW, C, window_size, window_size) -> (B*nH*nW, C, window_size, window_size)
    windows = windows.view(B * nH * nW, C, window_size, window_size)
    
    return windows, (H_pad, W_pad)
```

### 2. `window_reverse` - 窗口合并

```python
def window_reverse(windows: torch.Tensor, window_size: int, H_pad: int, W_pad: int,
                   H_orig: int, W_orig: int) -> torch.Tensor:
    """
    将窗口特征合并回完整的2D特征图
    
    输入: (B * num_windows, C, window_size, window_size)
    输出: (B, C, H_orig, W_orig)
    """
    # Step 1: 计算窗口数量和batch size
    nH = H_pad // window_size
    nW = W_pad // window_size
    B = windows.shape[0] // (nH * nW)
    C = windows.shape[1]
    
    # Step 2: 分离batch和窗口维度
    # (B*nH*nW, C, window_size, window_size) -> (B, nH, nW, C, window_size, window_size)
    x = windows.view(B, nH, nW, C, window_size, window_size)
    
    # Step 3: 调整维度顺序，准备合并
    # (B, nH, nW, C, window_size, window_size) -> (B, C, nH, window_size, nW, window_size)
    x = x.permute(0, 3, 1, 4, 2, 5).contiguous()
    
    # Step 4: 合并窗口，恢复完整特征图
    # (B, C, nH, window_size, nW, window_size) -> (B, C, H_pad, W_pad)
    x = x.view(B, C, H_pad, W_pad)
    
    # Step 5: 移除padding，恢复原始尺寸
    if H_pad > H_orig or W_pad > W_orig:
        x = x[:, :, :H_orig, :W_orig]
    
    return x
```

## 📊 维度变换示例

假设输入特征图：
- Batch size: B = 2
- Channels: C = 64
- Height: H = 32
- Width: W = 32
- Window size: window_size = 8

### 窗口分割过程

```
输入: (2, 64, 32, 32)
  ↓
Padding (如果需要): (2, 64, 32, 32)  # 32能被8整除，无需padding
  ↓
重塑: (2, 64, 4, 8, 4, 8)  # nH=4, nW=4
  ↓
调整维度: (2, 4, 4, 64, 8, 8)
  ↓
合并batch和窗口: (32, 64, 8, 8)  # 2*4*4=32个窗口
```

### 窗口合并过程

```
输入: (32, 64, 8, 8)  # 32个窗口
  ↓
分离batch和窗口: (2, 4, 4, 64, 8, 8)
  ↓
调整维度: (2, 64, 4, 8, 4, 8)
  ↓
合并窗口: (2, 64, 32, 32)
  ↓
移除padding: (2, 64, 32, 32)  # 无padding，保持不变
```

## 🎯 在 RTHD 中的应用

### `_process_view` 方法

```python
def _process_view(self, view: torch.Tensor, view_name: str) -> torch.Tensor:
    """处理单个视图，支持局部滑窗和全局平铺"""
    B, C, H, W = view.shape
    
    if not self.use_local_window:
        # 全局平铺版：直接对整个特征图进行扫描
        out = self.vmamba_2d(view)
    else:
        # 局部滑窗版：
        # Step 1: 窗口分割
        windows, (H_pad, W_pad) = window_partition(view, self.window_size)
        # windows: (B*num_windows, C, window_size, window_size)
        
        # Step 2: 对每个窗口独立进行VMamba扫描
        windows_out = self.vmamba_2d(windows)
        
        # Step 3: 窗口合并
        out = window_reverse(windows_out, self.window_size, H_pad, W_pad, H, W)
    
    return out
```

## 💡 关键优势

### 1. 计算复杂度对比

假设特征图尺寸为 H×W = 32×32，window_size = 8：

**全局平铺**：
- 序列长度：32 × 32 = 1024
- Mamba 复杂度：O(1024 × C)

**局部滑窗**：
- 窗口数量：(32/8) × (32/8) = 16
- 每个窗口序列长度：8 × 8 = 64
- Mamba 复杂度：O(16 × 64 × C) = O(1024 × C)

虽然总计算量相同，但局部滑窗的优势在于：
- **更好的并行性**：16 个窗口可以并行处理
- **更小的中间激活**：每次只处理 64 长度的序列
- **更强的局部建模**：每个窗口专注于局部特征

### 2. 显存占用对比

**全局平铺**：
- 中间激活：(B, 1024, hidden_dim)

**局部滑窗**：
- 中间激活：(B×16, 64, hidden_dim)
- 虽然总量相同，但可以分批处理，降低峰值显存

## 🔬 与 Swin Transformer 的对比

| 特性 | Swin Transformer | RTHD 局部滑窗 |
|-----|-----------------|--------------|
| 窗口类型 | 不重叠窗口 | 不重叠窗口 |
| 窗口大小 | 7×7 | 8×8 (可配置) |
| 窗口移位 | 有 (Shifted Window) | 无 |
| 注意力机制 | Self-Attention | Mamba (SSM) |
| 跨窗口交互 | 通过移位实现 | 通过三视图融合实现 |

**RTHD 的创新点**：
- 不需要窗口移位（Shifted Window），因为三视图融合已经提供了跨区域的信息交互
- 使用 Mamba 替代 Self-Attention，线性复杂度
- 结合三视图分解，在不同视角下进行局部建模

## 🛠 参数调优建议

### window_size 选择

| 特征图尺寸 | 推荐 window_size | 窗口数量 |
|-----------|-----------------|---------|
| 128×128 | 16 | 64 |
| 64×64 | 8 | 64 |
| 32×32 | 8 | 16 |
| 16×16 | 8 | 4 |

**原则**：
- 特征图越大，window_size 可以越大
- 保持窗口数量在合理范围（16-64）
- window_size 应该是 2 的幂次（便于计算）
